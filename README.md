# MHServer

Сервер для домашнего использования, с целью замены [Google Drive](https://drive.google.com), [Yandex Disk](https://360.yandex.ru/disk/) и т.д.

## Системные требования

* Linux с systemd
* [MariaDB](https://mariadb.org/) (Только для главного сервера)

Установить зависимости вы можете с помощью пакетного менеджера вашего дистрибутива. Пример для `Arch Linux`:

``` bash
sudo pacman -S mariadb
```

## Установка

Скайте последнюю версию [из списка релизов](https://github.com/braginantonev/mhserver/releases) сервера, распакуйте скачанный архив и запустите скрипт настройки:

``` bash
mkdir /tmp/mhserver-build && tar -zxvf путь_до_архива/mhserver.tar.gz -C /tmp/mhserver-build
cd tmp/mhserver-build/scripts
./install.sh
```

> [!INFO]
> При установке на вторую машину в локальной сети, создавать базу данных не обязательно и не рекомендуется
>
> [!WARNING]
> При развёртывании системы сервером, пожалуйста убедитесь, что вторичные машины должны слушать только свой адрес в локальной сети. Единственный сервер с доступом в сеть &mdash; главный. Остальные должны быть зависимостями.

## Конфигурация

Конфигурация производится в `server.conf`, который находится рядом с бинарником в `/opt/mhserver`. В секции `[server]` укажите адрес и порт, который сервер будет слушать. IPv6 указывается без фигурный скобок. Пример настройки главного сервера:

``` toml
[server]
address = "3a10:1270:11a6:18ac:1012:1b2b:f5ca:71f" // адрес сервера
port = 30543
```

И вторичной машины:

``` toml
[server]
address = "192.168.1.15" // используйте только локальную сеть
port = 30543
```

Подобно секции `[server]`, если вы настраиваете вторичную машину, то также вам нужно указать адрес и порт базы данных в секции `[database]`.

По желанию вы можете включить или выключить любой сервис. Самыми главными пожалуй считаются: `auth` и `files` сервисы. Если сервисы имеют зависимости, то их также нужно указать. Пример для файлового и музыкального сервиса на вторичной машине:

``` toml
[services.files]
enabled = false // файловый сервис развёрнут на главной машине

[services.music]
enabled = true

[services.music.dependencies]
// используем адрес и порт главного сервера, на котором развёрнут файловый сервис
files = { address = "3a10:1270:11a6:18ac:1012:1b2b:f5ca:71f", port = 30543 }
```

В случае, если у вас одна единственная машина (а в большинстве случаев это именно так), то в качестве адреса и порта зависимостей сервиса используйте тоже значение, что и для самого сервера:

``` toml
[server]
address = "192.168.1.15" 
port = 30543

[services.images.dependencies]
files = { address = "192.168.1.15", port = 30543 }
```

### Настройка пользовательских пространств

> [!INFO]
> Пропустите этот этап, если не собираетесь разворачивать файловый сервис

Файловому сервису необходимы пользовательские пространства (`uspace`) для работы. В них он хранит файлы пользователей. Пространства хранятся в каталоге `uspace` рядом с бинарником.

По сути своей, пользовательское пространство &mdash; это каталог `.mhserver`. Он может находится в любом каталоге, в том числе и на другом примонтированном устройстве (по сути поддержка нескольких дисков). Чтобы сервер не бегал по всей файловой системе в поисках пространств, в каталоге `uspace` создаются символьные ссылки на них.

Чтобы добавить пользовательское пространство, используйте скрипт:

``` bash
./create_uspace /путь_до_каталога
```

Если у вас закончилось место на диске и вы решили заменить его на новый, то вам также нужно обновить и ссылку (если путь примонтированного устройства поменялся). Важно, что битые ссылки не будут читаться сервером. Поэтому, самый нормальный способ обновить ссылку: воспользоваться скриптом вновь и заменить битую ссылку на новую, например, для битый ссылки `0`:

``` bash
./create_uspace /путь_к_новому_диску
cd uspace && sudo mv 1 0
```

### Сервис

Если по каким-то причинам вам необходимо залезть в базу данных или поменять `JWT` сигнатуру, то секреты хранятся в `.env` файле. Он принадлежит системному серверному пользователю и не доступен для чтению любым пользователям, поэтому используйте права суперпользователя:

``` bash
sudo cat /opt/mhserver/.env
```

После настройки не забудьте включить сервис сервера:

``` bash
sudo systemctl enable --now mhserver.service
```

## Использование

Для регистрации на сервере, вам также понадобится указывать специальный ключ. Вы можете посмотреть их с помощью скрипта:

``` bash
./register_keys -S --db_pass=пароль_от_базы_данных
```

И сгенерировать пятёрку новых:

``` bash
./register_keys -G --db_pass=пароль_от_базы_данных
```

> [!INFO]
> Имейте ввиду, что каждый ключ регистрации &mdash; одноразовый. Не раздавайте ключи кому попало, всё же это ваш личный сервер.

## API

Сервер работает на `GRPC`, поэтому вы можете создавать свои клиенты из `.proto` файлов. Они расположены в каталоге `proto/`.

## FAQ

### Как продлить TLS или корневой сертификат, если они просрочены?

Вы можете воспользоваться скриптом настройки сертификата:

``` bash
cd /opt/mhserver/scripts
./create-ssl-cert.sh
```

Вы также можете использовать данный скрипт для просмотра срока жизни вашего сертификата.
